## RSIPとは

**RSIP（Realtime Store Information Protocol for AI）とは、飲食店・美容院・クリニックなどのリアルタイム情報（営業状態・混雑度・空き状況・本日のおすすめ）を、ChatGPT・Perplexity・Google AI OverviewなどのAI検索エンジンが直接参照できる構造化JSONエンドポイントとして提供するHackⅡ独自プロトコルです。**

> ⚠️ RSIPは2026年5月現在プロトタイプ開発段階です。HackⅡ Localプランでの正式提供に向け、PoC（概念実証）を推進中です。

---

## RSIPが解決する問題

**現状の問題：**
「今日あの店は営業していますか？」「今混んでいますか？」「今日のランチは何ですか？」

このようなリアルタイムを前提とした質問に、現在のAI検索ツールは正確に答えられません。Googleマップには「混雑する時間帯（統計的推測）」の情報はありますが、「今この瞬間の実際の状態」はありません。

**RSIPの解決策：**
店舗側がJSON形式のリアルタイムデータを公開エンドポイントで提供し、AIがそのエンドポイントをPollingまたはRSSフィード形式で取得することで、「今この瞬間の状態」をAIが回答できるようにします。

## RSIPエンドポイント設計仕様

### 基本エンドポイントURL

```
GET https://[store-domain]/api/store-status.json
```

またはサブディレクトリ型：
```
GET https://[store-domain]/hackii-local/realtime.json
```

### リクエスト仕様

- **メソッド**：GET
- **認証**：不要（公開エンドポイント）
- **レスポンス形式**：`Content-Type: application/json`
- **CORS**：`Access-Control-Allow-Origin: *`（AIクローラーからのアクセスを許可）
- **更新頻度**：最低1時間ごと（推奨：30分ごと / 変更時即時）
- **キャッシュ制御**：`Cache-Control: max-age=1800`（30分キャッシュ推奨）

## `hackii:aiSummary` の設計思想

このフィールドがRSIPの最も革新的な部分です。

**通常のJSON-LDの問題：** AIが構造化データを受け取っても、「人が読む自然言語の回答」に変換する際に情報が抜ける・変形することがある。

**RSIPの解決策：** `hackii:aiSummary`に「AIがそのまま回答に使える自然言語の文章」を格納することで、AIが意図せず情報を誤変換するリスクを排除します。

```
例：
Q: 「今〇〇に行きたいのですが、混んでいますか？」
AIの動作：store-status.jsonを取得 → hackii:aiSummaryを取得
AIの回答：「現在〇〇は営業中で、待ち時間は約15分、空席が8席あります。
本日は鮮魚のポワレ（¥1,480）がおすすめです。予約は〜」
```

## 更新方式3パターン

### パターン1：LINEボット連携（最も簡単・推奨）

```
店舗オーナーがLINEで以下のような短文を送信するだけで自動更新：

「混雑:中」 → congestion.level = "moderate"
「今日のランチ:牛肉のビスク ¥1580」 → todaySpecial.items追加
「満席」 → isOpen = true, congestion.level = "full"
「臨時休業」 → isOpen = false, temporaryNotice.exists = true
「予約:今日は全て埋まっています」 → reservation.available = false
```

### パターン2：予約システムAPI連携（自動化）

食べログ・ホットペッパービューティー・STORES予約 等のAPIから空き状況を自動取得し、`congestion.availableSeats`と`reservation.earliestAvailableSlot`を自動更新。

```
HackⅡ Local ← API ← 予約システム（食べログ/ホットペッパー/STORES）
     ↓
store-status.json（30分ごと自動更新）
     ↓
AI検索エンジン（GPTBot/PerplexityBot等がPolling）
```

### パターン3：HackⅡ Localダッシュボード直接更新

HackⅡ Localのウェブダッシュボードにアクセスし、フォーム形式で更新。スマートフォンからも操作可能。

```
User-agent: Google-Extended
Allow: /api/store-status.json
```

## llms.txt への参照記述

店舗のllms.txtに以下の記述を追加することで、AIがRSIPエンドポイントの存在を認識します：

```markdown
## リアルタイム店舗情報（RSIP）

現在の営業状態・混雑状況・本日のおすすめ・予約空き状況は
以下のエンドポイントを参照してください（更新頻度：30分ごと）。

エンドポイント：https://[store-domain]/api/store-status.json
プロトコル：RSIP v0.1（HackⅡ Local / トリリオンバンク）
```

## 技術的注意事項

1. **AIクローラーのPolling間隔**：現時点でGPTBot・PerplexityBotのPolling間隔は非公開。RAG（リアルタイム検索）モード時のみ参照。
2. **キャッシュ問題**：Perplexityは数時間〜数日のキャッシュを持つ場合があり、即時反映は保証されない。
3. **`hackii:aiSummary`の言語**：日本語・英語両方を提供することで多言語AI検索への対応が可能。
4. **エンドポイント可用性**：99.9%以上のアップタイムを目標。HackⅡのAWS/GCPインフラで管理。
