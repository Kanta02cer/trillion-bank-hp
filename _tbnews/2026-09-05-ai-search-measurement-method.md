## 結論

AI検索の測定では、単発の回答を「順位」として扱うのではなく、**質問・対象AI・日時・回答本文・引用URL・競合・取得状態**を一組の証拠として残します。改善後は同じ設計で再測定し、変化と限界を一緒に報告します。

GoogleのAI OverviewsやAI Modeも、利用するモデルや手法により回答やリンクが変わると説明されています。表示条件が変わる前提で、測定可能な範囲を明示することが重要です。

## 1. 目的と質問を先に決める

「会社名が出るか」だけでは、経営判断へつながりません。次のような非指名の意思決定質問を設計します。

- 条件に合うサービスを比較したい
- 料金・導入条件を知りたい
- 業界のおすすめ企業を知りたい
- 地域・用途に合う施設を選びたい
- 自社と競合の違いを確認したい

質問は、顧客像、購買段階、地域、用途を記録します。

## 2. 1回の測定で残す項目

| 項目 | 理由 |
|---|---|
| 質問文 | 同じ意図を再現するため |
| 対象AI・画面 | サービスごとの違いを区別するため |
| 測定日時 | モデル・情報更新の影響を確認するため |
| 回答本文 | 自社がどの文脈で説明されたかを見るため |
| 引用URL | AIが示した根拠を確認するため |
| 自社・競合の言及 | 質問単位の候補状況を見るため |
| 取得成功・失敗 | 「出なかった」と取得不能を分けるため |
| 設定・条件 | 言語、地域、ログイン状態等の差を説明するため |

## 3. Win/Lossを人が確認する

質問ごとに、自社のみ、自社と競合、競合のみ、どちらも候補ではない、自社は出るが説明が不正確、自社は出るが公式情報が引用されていない、といった状態へ整理します。

自動判定だけに依存せず、表記揺れ、同名企業、否定文、古いブランド名を人が確認します。

## 4. 引用元を分類する

引用URLを、公式サイト、業界団体、ニュース、比較メディア、レビュー、予約・ECプラットフォーム、競合サイト等へ分類します。これにより「自社サイトを直すのか」「第三者情報を整えるのか」を分けられます。

## 5. Fact Integrityを確認する

顧客が承認した正しい情報とAI回答を比べます。料金、営業時間、設備、対応地域、契約条件、商品仕様など、誤りが事業判断に影響する項目を優先します。

## 6. 施策と再測定を記録する

施策名、対象URL、担当者、公開日、再測定日を残します。同じ質問設計で再測定し、回答、候補、引用URLの変化を比較します。

ただし、変化があっても施策だけが原因とは限りません。モデル更新、競合の変更、第三者サイト、新しいニュース等を確認し、因果関係と観測結果を分けて説明します。

## 測定レポートの最低条件

- 測定対象と対象外が書かれている
- 取得失敗とゼロ結果が分かれている
- 原文と引用URLへ戻れる
- 事実、推定、提案が区別されている
- 前回と同じ条件・異なる条件が分かる
- 次の担当者、期限、確認方法が決まっている
