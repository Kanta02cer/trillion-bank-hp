# AirReach 担当者ダッシュボードの改善（#152・2026-10-07）

担当者が「今日、どの顧客の何を終わらせるか」をすぐ判断でき、顧客の取り違え・古い数字での報告・入力の消失・誤削除を防ぐための改善。
2026-10-06 の調査（社内資料）の12項目に対応した。検証はすべて架空データ（サンプル美容室 Hana など・`.example` のドメイン）で行い、本番の DB・データには触れていない。

## 12項目の対応

| # | 項目 | 対応 | 主な場所 |
|---|---|---|---|
| 01 | レポートの数字の鮮度 | 下書きの集計日時と、集計に使った材料（診断日・AI 計測・Search Console/GA4 の期間）を出す。いまの材料で集計し直した結果と比べ、変わった点（例 67点→93点）を「新しいデータがあります」として出す。下書きは「数字を最新化」で `compiled` だけを入れ替え、結論・施策・判断事項はそのまま。確認中・承認済み・公開済みは数字を変えず、下書きに戻す既存の手順（確認・承認のやり直し）を案内する | `reportEditor`・`AirReachStaff.freshness` |
| 02 | 入力の保護 | 下書きの文章を自動保存（入力から1.5秒）。「保存中／保存済み（時刻）／未保存の変更／失敗」を上部に常に表示。入力のたびに端末へ控え（`localStorage` のレポート ID ごと）を残し、失敗・再読み込みのあとに「保存されていない入力」を戻せる。画面の移動・顧客の切り替え・ログインの状態の変化の前に保存し、未保存のまま閉じる・再読み込みするときは確認。保存は常にそのレポートの ID に、下書きのときだけ（状態は送らない）。確認依頼の前に最新の入力を保存。ボタンの連打を防ぐ。トークンの自動更新では画面を作り直さない | `reportEditor`・`AirReachStaff.Autosave` |
| 03 | 削除の保護 | サイト・閲覧メンバー・AI 計測・検索と訪問の数字・施策の削除で、顧客名・対象・日付を出す画面内の確認（やめる・Esc・外側のクリックでは消さない）。削除後60秒以内は「取り消す」で同じ ID・同じ中身で戻せる（画面を移ると取り消せない。AI 計測は定期計測の実行記録とのつながりは戻らない） | `confirmBox`・`guardedDelete` |
| 04 | 顧客の引き継ぎ | Studio へのリンクを1つの作り方にまとめ、顧客 ID・名前・サイト・業種・画面（`#generator` など）を必ず URL で渡す。レポートの「直す材料で下書きを作る」も同じ。顧客が分からないときは「顧客なし」で開く（前の顧客を使わせない） | `AirReachStaff.studioLink`・`studioHref` |
| 05 | 比較期間 | 検索・訪問のタイル・推移・数字の一覧に、対象期間（全期間／途中集計 〜m/d・日数／期間の記録なし）と取得日時を出す。前月と増減を出すのは両方が全期間（または同じ日数）のときだけ。月の途中・期間が分からないときは前月の値を参考として出し、悪化・改善を断定しない。取得日時は今後の Google 取得から記録（`metrics.fetched_at`）。期間の記録が無い既存のデータは推測で補わない | `AirReachStaff.periodOf/compare`・`trafficTile`・`trendCard` |
| 06 | ホームの最上部 | 「今日の作業」：顧客名・対象月・次にやる作業（7工程の何番目か・理由）・ボタン・報告の期限・担当・残りの工程・確認待ちの依頼・今月のレポートの状態。数字は小さく1行にし、AI 別の割合・分子と分母・対象期間は「内訳を開く」。AI の詳しい結果は折りたたみ | `todayCard`・`compactNumbers` |
| 07 | 顧客一覧 | 名前で探す・「自分の担当／期限が近い・超過／AI 未計測／Google 未取得／差し戻し／依頼あり」で絞り込み（件数つき）。期限超過→期限が近い→差し戻し→依頼の順に並べる。担当と毎月の報告期限（日）は顧客ごとに設定（新しい列。未設定は「未設定」と出す）。代理店デモの入口は一覧の下の折りたたみへ | `clientList`・`AirReachStaff.triage/dueOf`・migration |

| 09 | メニューと7工程 | メニューの「毎月の作業」をホームの7工程と同じ名前・同じ番号（1〜5・6・7）で並べ、細かい画面は「詳しく見る」へ。7工程の見出しにも番号。既存の URL（`#/c/<id>/<節>`・Studio の `#panel`）はそのまま開ける | `airreach-nav.js`・`monthPlan` |
| 10 | スマートフォン | 上に顧客名と現在の画面名を常に出し、メニューは「メニュー」ボタンで縦に開く（横スクロールで現在地が隠れない）。開くと現在の項目にフォーカス。フォーカスの枠を出す | `sideHtml`・CSS |
| 11 | 入力のラベル | レポートの13欄すべてに見えるラベルを結び付けた（結論1（必須）・結論2〜3（任意）・施策1〜3 の施策名・担当（任意）・期限（任意）・判断事項（任意））。「1〜3件。最低1件は必須（確認を依頼する条件）」を見出しの下に明記 | `reportEditor` |

## 残る制約

- 自動保存は1人で編集する前提。同じ下書きを2人が同時に開くと、後から保存した方が残る（版の確認はしていない）
- 削除の取り消しは、その画面で60秒以内だけ（ゴミ箱のような長期の復旧は無い）
- 「渡した」の記録は持たない（判定しない）。必要なら施策に「共有済み」の状態を足す設計が要る
- 過去に取り込んだ検索・訪問の数字には取得日時が無い（「期間の記録なし」または取得日時なしで表示）
- Studio 側のスマートフォン表示は今回の対象外（メニューの番号だけそろえた）

## お客様の依頼の「補足」（2026-10-07・migration 20261007190000）

- お客様は、競合・キーワード・質問の追加を依頼するときに「補足（任意・500文字まで）」を書ける。担当者の「お客様からの依頼」に「お客様の補足：…」として出る。お客様の「ご依頼と変更の記録」にも出る。
- 担当者の追加欄には補足の欄を出さない（その場で反映するため）。
- DB: `client_requests.note` と、5つの引数の `airreach_request_create(…, p_note)`。4つの引数の関数はそのまま残すので、適用の前後どちらの画面でも依頼は送れる。適用前に補足を書いた場合は、依頼だけ送り「補足は保存できなかったため、担当者に直接お伝えください」と出す。
- 適用: `python3 scripts/airreach-api/phase2-apply.py apply-request-note`（取り消しは `supabase/rollback/20261007190000_airreach_request_note_rollback.sql`）。
- 担当者へのお知らせ（メール等）はまだ無い。依頼は顧客一覧の「依頼」の印と、顧客ホームの「今日の作業」で気づく。
